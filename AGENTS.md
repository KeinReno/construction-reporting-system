# AGENTS.md — инструкции GPT-агентам

## Цель
Собрать работающий MVP строительной отчётности за 5 дней и посвятить последующие 9 дней исправлениям и полевым испытаниям.
Порядок приоритетов: сохранность данных > безопасность > корректность показателей > удобство > расширение ИИ.

## Общие правила
1. Перед работой прочитай TASKS.md, docs/PRODUCT.md и нужные контракты: docs/API.md, docs/DATA_MODEL.md, docs/REPORT_FORM.md, docs/PHOTO_RULES.md. Не перечитывай весь репозиторий без причины.
2. Меняй только назначенный компонент (android/, backend/, web/) и его тесты. Изменение общих контрактов согласовывай.
3. Не добавляй непрошенные функции, микросервисы, крупные рефакторинги и лишние библиотеки.
4. Данные отчёта структурированы; комментарий не заменяет поля. Отсутствие выполненной работы — отдельный формальный сценарий.
5. Android сначала сохраняет отчёт локально, затем синхронизирует. Используй стабильный UUID, идемпотентность, транзакции и серверное подтверждение полной доставки, включая обязательные вложения.
6. Сервер валидирует все поля и права. Автор определяется из авторизованной сессии, а не из employee_id клиента. Любой запрос к чужому объекту должен отклоняться.
7. Не публикуй PostgreSQL в интернет. Не коммить персональные данные, реальные клиентские фото, токены, пароли или конфигурации с секретами.
8. Числовые расчёты выполняет сервер. ИИ вызывает только разрешённые функции чтения, показывает фильтры/период/источники и не записывает данные.
9. Время события хранится в UTC; дата работ — календарная дата на объекте. Не путай дату съёмки, дату работ и время получения.
10. Не говори, что тест пройден, если не запускал. При отсутствии Android SDK/устройства/БД явно укажи блокер.
11. Пиши минимум кода, достаточный для требований. Не «улучшай» соседние модули вне задачи.
12. Не изменяй протокол отправки без совместного обновления Android, Backend и API.md.

## Рабочий цикл
Постановка → минимальная реализация → целевые тесты → фиксация в TASKS.md → короткий итог.
Отчёт: (1) что сделано, (2) изменённые файлы, (3) команда и результат тестов, (4) блокеры и риски, (5) следующая задача.

## QA-агент
По умолчанию только воспроизводит проблемы и оформляет дефекты: шаги, ожидалось/получилось, серьёзность, предполагаемая область. Исправляет основной разработчик. После исправления QA повторяет проверку.

## Definition of Done
Контракт соблюдён, функция воспроизводима, обязательные тесты реально запущены либо их отсутствие явно отмечено. «Код написан» не означает «готово к эксплуатации».
