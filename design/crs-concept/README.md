# CRS — концепция 01

Изолированный браузерный прототип Web заказчика и будущего Android-интерфейса. Не подключается к API CRS. Только синтетические записи, собственные SVG-иллюстрации вместо фотографий; внешних запросов и зависимостей нет.

## Запуск

Из корня репозитория: `.venv\Scripts\python.exe -m http.server 58515 --bind 127.0.0.1 --directory design/crs-concept`

Открыть `http://127.0.0.1:58515/`. Альтернатива без сервера — открыть `index.html` браузером (поведение localStorage для file URL зависит от браузера).

## Экраны

- `#web/overview`: обзор за период, объекты и очередь проверки.
- `#web/objects`, `#web/object?site=north|east|south`: список и карточка объекта.
- `#web/reports`: журнал. `#web/report`: проверка текущей доставленной смены.
- `#web/money`: расходы, поступления и авансы раздельно.
- `#web/analytics`, `#web/source`, `#web/record`: расчёт по записям и переход к источнику.
- `#app/today`, `#app/form`, `#app/preview`: смена, заполнение и демонстрационная отправка.

Октябрь 2026 — один синтетический месяц в `data.js`. Итоги считаются из записей. На телефоне: Обзор, Объекты, Отчёты, Ещё.

Дополнительно: история/профиль аапп. Единый сценарий: заполнить → отправить → открыть Web → вернуть с причиной → уточнить в аапп → повторно отправить → принять. При демоофлайн отчёт попадает в очередь и становится виден в Web только после кнопки восстановления связи.

## Дизайн и продуктовые решения

Графитовая система с янтарным акцентом; Segoe UI, два веса. Web показывает состояние объекта и очередь решений; аапп ведёт через текущую смену. `rule/one-primary-action`, `rule/structure-before-containers`, `rule/preserve-user-input`, `rule/cover-reachable-states`, `rule/name-object-scope-consequence`.

Задача пользователя: бригадир фиксирует смену, заказчик проверяет результат. Объект действия — одна синтетическая смена. Отправка меняет только локальное демосостояние, возврат открывает редактирование, принятие закрывает его. Роли переключаются вкладками концепции, это не авторизация. Успех — самостоятельное прохождение сценария и выбор композиции обеих платформ. Эксплуатация, реальные роли, график смен, справочники и политика ИИ остаются в SPEC-00.

Использованы ui-design Build: aesthetic-direction, design-guidelines; colors, dashboards, form-controls, surfaces, buttons, navigation, responsive-design, typography. Sites: local-only preview. Мобильные цели увеличены до 48px в соответствии с задачей полевого ввода.

## Границы

localStorage — только иллюстрация сохранения, не Room/WorkManager и не безопасное хранилище. Сетевая очередь имитируется, внешней доставки нет. Фото — статические иллюстрации без загрузки. Денежные итоги и объёмы считаются из записей месяца, серверный контракт не меняется. В форме смены несколько работ, материал, техника и чек к расходу. Не является APK, production-версией или подтверждением работы на телефоне заказчика. Существующие Web/Android/Backend не изменены.
