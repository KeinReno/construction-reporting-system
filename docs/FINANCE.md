# FINANCE — минимальная модель денежных операций

**Рабочее решение от 28.10.2026:** минимальный денежный журнал внутри отчёта. Это управленческие сведения, не бухгалтерия.

## Операции
- `expense` — подтверждённый расход (топливо, проживание, покупка инструментов, оплата наёмных работ, транспорт).
- `funding_received` — поступление/выделение средств для объекта.
- `advance_issued` — выданные авансы/командировочные сотрудникам (разделить категории по решению заказчика; не считать аванс расходом автоматически).
- `adjustment` — корректировка ранее введённой операции с обязательной ссылкой и причиной; можно реализовать ревизией, не удаляя первичный след.

У каждой операции: категория, дата операции (может отличаться от даты отчёта), amount_minor (целое количество копеек, positive), RUB, комментарий, опциональный чек, внешний референс, report_id.

## Правила аналитики
1. Показывать расходы и финансирование отдельно; остаток = согласованная формула после B05, не равен прибыли.
2. `advance_issued` — отдельно от расходов, пока не утверждена схема отчётности авансов.
3. Накопительные «за период потрачено N» — отчётная сводка, не транзакция; при импорте истории не дублировать.
4. Записи о закупке ресурса и его фактическом расходовании — разные сущности; не считать один чек израсходованным материалом.
5. Исправление поздно сообщённого расхода сохраняет исходную дату операции и время ввода/корректировки.
6. Никаких начислений зарплаты, налогов, счетов-фактур и двойной записи в MVP.

## UI
Секция «Расходы и деньги» с кнопкой «Добавить операцию», типом из справочника, суммой, датой и фото чека. В Web фильтры по видам операций, объектам и датам. Данные только из первичных операций.

**OPEN:** что считать расходом компании, как учитывать командировочные/авансы и валюту; эти правила утверждает заказчик.

## Фактически реализовано

Android-форма, серверный контракт, карточка Web и локальная аналитика поддерживают `expense`, `funding_received`, `advance_issued`. Сумма хранится в целых копейках без округления, дата операции отделена от даты отчёта, ID записи сохраняется при правке. История ревизий хранит прежний документ; текущая аналитика не складывает старые ревизии повторно. Категория вводится текстом. Чек связывается с конкретной операцией через `receipt_photo_id`: Android позволяет добавить одно фото из секции операции либо выбрать уже добавленное. Фото чека нельзя удалить до удаления связанной операции. Отдельного фильтра по дате операции, самостоятельного финансового реестра, начального остатка и итогового баланса пока нет. Операция `adjustment`, внешний референс и валюта в контракте не реализованы; исправление делается ревизией отчёта с причиной.
