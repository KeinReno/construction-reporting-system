# PRODUCT — MVP / границы продукта v0.2

## Задача
Перевести нерегулярные сообщения строительных бригад в стандартизированные отчёты и достоверную управленческую аналитику. 3–4 ответственных, несколько строительных объектов, 10–20 отчётов в день. Реальные образцы показывают работы, состав бригады, время выезда/допуска, простои, расходы и фотографии. **Персональные данные из исходников не копировать в репозиторий.**

## Роли
- Employee/Foreman: Android, назначенные объекты, создание/история/редактирование возвращённых отчётов.
- Manager: разрешённые объекты, ожидание отчётов, проверки, аналитика и просмотр источников.
- Admin: аккаунты, объекты, справочники, назначения, политики форм, обслуживание.
- Работник в составе бригады — запись `workers`, НЕ обязательно учётная запись `users`.

## Единица отчёта
**PROPOSED B01:** ответственный отправляет сменный отчёт по одной бригаде/объекту/дате; несколько работ/материалов/денежных операций/инцидентов в одном отчёте. Не запрещать дополнительный отчёт жёстким уникальным индексом, пока заказчик не утвердил правило.

## Путь сотрудника
Выбрать объект → дату/бригаду → тип `work` или `no_work` → состав и время (если включено) → работы/материалы/деньги/инциденты/планы (по установленным правилам) → фото → свободный комментарий по желанию → сохранить локально → отправить. При отсутствии сети сохранить очередь и повторить позже.

## Контроль
На сервере сохранять назначения и ожидаемые отчёты с дедлайнами. «Не отчитался» только при активном ожидании и превышении дедлайна. При `no_work` фиксировать причину/при необходимости простой — отчёт считается полученным. Сетевое подтверждение отдельно от проверки содержания.

## Web
Главная сводка по объектам, дисциплина отчётности (ожидался/доставлен/проверен/возвращён), динамика работ с единицами, материалы (приход ≠ расход), инциденты/простой, денежные операции раздельно по видам, детальный журнал и фото, фильтры объект/дата/бригада/сотрудник; мобильный интерфейс iPhone/Android.

## ИИ
Серверные выборки + read-only LLM-объяснения с периодом, ссылками на исходники и явными ограничениями. Ключи/платёжные данные отдельно; работоспособность Web не зависит от доступности ИИ.

## MVP — обязательный минимум (при подтверждении B01–B14)
Пользователи/объекты/назначения; конфигурируемые формы и справочники; несколько работ/материалов; `no_work`; локальная очередь и фото; идемпотентный API; контроль полученных/ожидаемых; графики и первичка; финансовые записи (при согласовании B05); роли/ACL/аудит; backup/restore; минимальные аналитические функции.

## Не включаем
Импорт истории из MAX, полноценную бухгалтерию и расчёт зарплат, продвинутую ML-прогностику, коммерческий multi-tenant, сложные производственные планы, полную интеграцию с Orion. План-факт только при введённых планах.

## Критерий коммерческой готовности
Функции нужны на реальном Android и Windows заказчика, протестированы офлайн и с VPN/без, есть восстановление БД и согласованные роли. Пятый день = интегрированный MVP, четырнадцатый = решение о пилотной эксплуатации по проверкам.
