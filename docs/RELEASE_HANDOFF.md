# Граница завершения и ввод в эксплуатацию

## Техническая поставка
PR #2 содержит проверяемое ядро Android/API/Web, локального аналитика, административный интерфейс, ручной исторический импорт, миграции, backup/restore и Windows runtime ZIP. Windows-инструкция — WINDOWS_INSTALL.md, импорт — MANUAL_IMPORT.md. APK 0.3.0 настраивает HTTPS перед первым входом, не требует адреса клиента в публичном исходном коде. CI проверяет настоящий HTTPS Worker, Room, SQLite/PostgreSQL и PowerShell на Windows. Точные запуски и исходы фиксируются в PR/QA.

Это завершение технического подмножества, а не утверждение открытых правил или приёмка реальной площадки. Не ставить APPROVED в SPEC-00 без ответа владельца. Пользователь поручил продолжать до завершения; доступа/исходных фактов ниже это не добавляет.

## Решения, которые нельзя выдумать в коде
| Пункт | Подготовленное предложение из SPEC-00 | Что требуется от владельца |
|---|---|---|
| B01/B02 | Ответственный × бригада/объект/смена, дополнительные отчёты допустимы; ожидание только по назначенной смене | Единица отчёта, смены, timezone/дедлайн, выходные/отмены |
| B03/B04 | Структурированная форма; работники отдельно от логинов; snapshot состава | Обязательность полей и составов, подрядчики, времена |
| B05 | Раздельные расходы/поступления/выдачи, integer копейки, без расчёта зарплаты | Включать ли деньги и какие операции/категории |
| B06/B07 | Фото по политике работ; каталоги + уточнение «Другое» | Требования к фото, реальные каталоги/единицы/материалы |
| B08/B09/B10 | Возврат с причиной; проверяемые KPI; необязательные планы | Подтвердить workflow, нужные KPI и планы смены |
| B11/B12 | PostgreSQL/фото на Windows, localhost API за HTTPS | Параметры ОС/ресурсов, оператор, домен/сертификат, доступ и тесты VPN/без |
| B13 | LLM только read-only по проверяемым агрегатам | Провайдер/ключ или локальная модель, бюджет и разрешённые данные |
| B14 | Приёмка по применимым сценариям | Ответственный, сопровождение, права на код и ключ подписи Android |

Наличие предложений не означает их согласование. До ответа материалы/деньги/составы/плановые ожидания/внешняя LLM остаются BLOCKED; публичная CI не может проверить телефон/Windows/сеть заказчика.

## Передавать безопасно
- Не публиковать пароли, токены, ключи подписи, реальные адреса/фото/переписки в PR.
- Адрес и доступ задаёт оператор на стороне клиента; пароль БД — приватный config, первый admin — интерактивный CLI.
- Для устойчивых обновлений подписать release-unsigned.apk своим постоянным keystore вне Git: `apksigner sign --ks PRIVATE_KEYSTORE --ks-key-alias PRIVATE_ALIAS --out app-release.apk app-release-unsigned.apk`, затем `apksigner verify --verbose app-release.apk`. Инструмент запросит пароль интерактивно. Ключ не генерируется и не выбирается за владельца.
- Debug APK подходит для проверки; ключ debug CI может изменяться между runner'ами. Не рассчитывать на него как на постоянную производственную подпись.

## Реальная приёмка
Вход/доступы → Android report/photo/receipt → Web review → revision → источник/аналитика; Wi-Fi/мобильная сеть с VPN/без; перезапуски процесса/телефона/Windows; backup/restore; контроль данных исторического импорта; подпись/обновление APK. До этих результатов коммерческий rollout не объявляется завершённым.
