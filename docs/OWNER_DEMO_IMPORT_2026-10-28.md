## Как разбирать историю

1. Создать приватный каталог вне репозитория для исходных сообщений и оригинальных вложений. Для каждого сообщения сохранить чат, устойчивый идентификатор/ссылку, автора по источнику, дату и время сообщения, полный текст, список вложений и контрольные суммы файлов. Сохранять порядок и исходник, не редактировать его при классификации.
2. Составить реестр сообщений с типом: отчёт о работе, отсутствие работ, денежная операция, материал, техника, событие/простой, план, контекст или неоднозначно. Одно сообщение может содержать несколько фактов; несколько сообщений могут относиться к одному дню. Связь фото с сообщением фиксировать только по данным источника.
3. Отдельно установить рабочую дату, объект, состав бригады, количество и единицу, дату денежной операции. Дата сообщения не подменяет рабочую дату. Суммы хранить в целых копейках; поступления, расходы и авансы разделять. Неизвестные поля оставлять неизвестными, а не нулевыми.
4. Подготовить таблицу сверки: исходное сообщение/фото → структурированная запись → раздел аналитики. Спорные места вынести в список уточнений. Сводные сообщения не превращать повторно в первичные денежные операции.
5. Создать отдельную локальную демобазу для владельца с доступом к исходным сообщениям и изображениям, не заменяя текущую учебную базу. Использовать существующий валидируемый импорт, сохраняя исходный текст и источник. Перед записью провести dry-run, затем сверить число записей, вложения, даты, суммы и показатели в Web.

## Критерии готовности

- Владелец открывает отдельный Web билд и видит только данные из предоставленных чатов с понятным периодом и источниками для каждого показателя.
- Все видимые даты представлены как `дд/мм/гггг`; интерфейс на русском. В хранилище допускается ISO-дата по контракту API.
- Фото открываются из соответствующего сообщения/отчёта; отсутствующие или спорные связи прямо обозначены.
- Графики считают только подтверждённые структурированные записи. «Ожидаемый отчёт», баланс и план-факт не вычисляются без утверждённых графиков, начального остатка и планов.
- Отдельная QA сверка по выборке и проверка запуска готового билда выполнены. Сборка не содержит открытых демо-паролей, если в ней есть реальные данные клиента.
