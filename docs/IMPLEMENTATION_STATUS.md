# IMPLEMENTATION_STATUS — 26.10.2026

Ветка `feat/mvp-core-bootstrap`, существующий draft PR #2. Это проверяемый технический MVP, **не завершённый коммерческий релиз**. SPEC-00 остаётся OPEN: технические изменения не утверждают B01–B14.

## Реализовано
- **Android:** Compose; несколько работ и `no_work`, фото; Room с неразрушающими миграциями 1→2→3→4; очередь WorkManager; локальные записи привязаны к аккаунту; token+owner хранятся одним зашифрованным Keystore-record. Кэш доступных объектов для ранее вошедшего пользователя. Частичная форма автоматически сохраняется в отдельной owner-scoped таблице, включая сырой ввод/фото/исправление; до восстановления UI не перезаписывает её начальными значениями. Enqueue и consume формы атомарны; поздние автосейвы отклоняются nonce. Открытие другого отчёта требует подтверждения замены текущего ввода. Лимиты API проверяются локально. Ошибки 4xx требуют проверки, временные ошибки повторяются. Восстановление receipt после потери ответа; сравнение серверного и локального payload; исправление возвращённых и отклонённых локальных отчётов с revision/reason.
- **Backend:** FastAPI/SQLAlchemy, роли и объектный/авторский ACL, PBKDF2, восьмичасовая сессия, logout/revoke и ограничитель входа для одного процесса. Идемпотентное создание и submit; optimistic locking для конкурирующих изменений; история с исходным payload, автором, временем и квитанциями прежних ревизий. Потоковый лимит фото, SHA256, проверка декодируемого изображения, неизменяемый путь UUID+SHA. Alembic 0001–0003 для SQLite/PostgreSQL. Пагинация журнала, единые фильтры периода/объекта.
- **Web:** вход/выход, журнал со всеми страницами API, фильтры, объёмы по сопоставимым единицам, дневная динамика, фото с авторизацией, история, проверка и возврат manager/admin. Ответы старой сессии/фильтра не перезаписывают новые данные.
- **Аналитик:** `/analytics/ask` с явным whitelist intent: summary/work_volume/no_work/site_timeline; точные Decimal-расчёты, период, источники и ограничения. Режим `local_analytics`; свободный вопрос не исполняется и не превращается в SQL. Внешняя LLM отключена до B13; Web работает независимо от неё.
- **Обслуживание:** локальный CLI создаёт admin/manager/foreman, объекты и назначения. Offline backup/verify/restore БД и зарегистрированных фото; manifest SHA256; восстановление только в новую БД и пустой каталог. PostgreSQL использует pg_dump/pg_restore.

## Совместимость
- Перед обновлением существующей bootstrap-БД: остановить API, сделать проверенную копию; сверить исходную схему; только для исходной схемы PR поставить `alembic stamp 0001`, затем `alembic upgrade head`. Новая БД: сразу `upgrade head`.
- Legacy timestamps сохраняются NULL: время миграции не выдаётся за время события.
- Старые Android drafts без ownerId сохраняются, но не назначаются следующему вошедшему пользователю. Автоматическая отправка заблокирована; требуется ручное восстановление владельца из локальной БД. Старую сессию нужно заменить повторным входом.
- Изменения неизвестных полей отклоняются 422 вместо незаметного удаления из отчёта. Текущий wire-контракт описан в API.md; целевая расширенная модель остаётся draft.
