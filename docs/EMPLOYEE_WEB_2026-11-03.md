# Простой Web для сотрудника — 03.11.2026

## Основание и границы

Заказчик попросил упростить систему, а детали предложил обсудить на встрече.
Владелец поручил начать работу, уточнил «не APK, а вебапп», затем запросил GitHub.
Это разрешение на отдельный браузерный сценарий сотрудника в дополнение к Android.
Серверные роли, модель отчёта, денежные правила и кабинет руководителя не пересматриваются.
SPEC-00 остаётся PARTIAL; графики смен, обязательность фото и итоговая полевая приёмка не утверждены.

## Аудит и направление

Проблема: рабочий сценарий растворялся среди навигации, показателей и секций.
Направление: журнал бригадира. Короткий, спокойный, прямой интерфейс.
Сначала объект, дата и результат смены; затем фото и одна кнопка отправки.
Объём вводится только если известен. Вместо фиктивной работы можно указать простой с причиной.
Материалы, деньги, техника, бригада, события и планы раскрываются по запросу.
Два раздела: «Отчёт» и «Мои отчёты». Возврат открывает замечание и исходный отчёт.
Графитовая палитра, один янтарный акцент и существующий IBM Plex сохранены.

Применены принципы [Unslop](https://github.com/heydamir/unslop), автор Damir Sokolovsky,
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/): сокращение визуального шума,
явная задача экрана, повседневные формулировки, минимум акцентов.
Реализация адаптирована к существующему CRS; удалённые скрипты не выполнялись.

## Запуск

1. Собрать `web`: `npm ci`, затем `npm run build`.
2. Запустить существующий API с подготовленной рабочей БД, например штатным
   `scripts/windows/Start-LocalPreview.ps1 -LocalOnly -NoBrowser`.
3. Запустить `scripts/windows/Start-EmployeeWeb.ps1`.
4. Открыть `http://127.0.0.1:58495/?mode=employee`, войти учётной записью сотрудника (`foreman`).

Тот же билд обслуживает оба кабинета: `/` — руководитель, `/?mode=employee` — сотрудник.
Дополнительный локальный Web на 58495 использует тот же API на 58494 и не копирует БД.
Администратор назначает сотруднику объекты штатным способом; клиент не создаёт пользователей.
Папка `web/dist` содержит только публичные файлы. Архив сборки не содержит БД, фото или паролей.

## Данные и ограничения

- Перед отправкой полный отчёт и фото атомарно записываются в IndexedDB. UUID не меняется при повторах.
- Черновик и очередь разделены по серверному ID сотрудника. Проверки полномочий выполняет API.
- Конкурирующие вкладки используют локальную версию; устаревшая вкладка блокирует перезапись.
- Возврат и исправление используют expected_revision; неизменённые многострочные сведения сохраняются.
- Неизвестная принадлежность техники не угадывается: перед отправкой нужен явный выбор
  «Своя»/«Наёмная» согласно действующему API. Деньги — целые копейки.
- Фото преобразуются в JPEG до 1920 px; исходное разрешение и метаданные не сохраняются в новом вложении.
- Очередь работает при открытой вкладке после входа. После закрытия браузера отправка не выполняется.
- Это Web, без APK и service worker. Первый вход/загрузка приложения требуют связи.
- Хранилище привязано к браузеру и адресу. Очистка данных сайта удалит неотправленные черновики;
  смена адреса не переносит их. Локальное хранилище не объявляется зашифрованным.
- Мобильный доступ извне и Safari на физическом iPhone в этом срезе не подтверждены.
