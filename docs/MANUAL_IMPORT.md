# Ручной импорт истории

Импортируется подготовленный оператором JSON-пакет по текущему контракту work/no_work. Это не экспортёр MAX и не автоматическое распознавание текста/фото. Никаких догадок о дате, авторе или связи фотографий. Бригаду, материалы и события можно добавить в поддерживаемом формате; финансовые операции и другие неподдерживаемые поля приводят к ошибке валидации, а не отбрасываются молча.

Вне Git создайте приватную папку с bundle.json и подкаталогом photos. За основу берите backend/examples/import-demo.json в репозитории или IMPORT_EXAMPLE.json в Windows ZIP. Демонстрационные UUID не применять к реальным объектам: для каждого отчёта создать стабильный client_report_id, site_id взять из разрешённых объектов. При повторной попытке UUID не менять.

- source_ref — проверенная ссылка/идентификатор исходного сообщения; всегда остаётся в локальном журнале результата. Для сохранения первичного сообщения на сервере передайте также необязательный `source`: `{"source_ref":"тот же идентификатор","text":"полный текст сообщения","reported_author":null,"message_date":null}`. Автор и дата здесь — только сведения из источника; если неизвестны, оставьте null. Дата сообщения и дата работ не равнозначны.
- data — полный API ReportData с явной рабочей датой. Автор — текущая серверная сессия; инструмент не имитирует аккаунт исторического автора. created_at/submitted_at отражают реальное время импорта, не подделывают прошлое.
- photos — список `{id,file,mime}`; относительные файлы только внутри папки пакета, PNG/JPEG/WebP, до 8 MiB и 40 млн пикселей. UUID списка должен точно совпадать с data.required_photo_ids, без повторов между отчётами.
- Максимум 500 отчётов за пакет; большую историю разделить на пакеты. Перечитать источник и проверить дату/объект/фото до применения.

Из backend/ установленного пакета:

```powershell
..\.venv\Scripts\python.exe -m app.import_reports C:\Private\history\bundle.json
..\.venv\Scripts\python.exe -m app.import_reports C:\Private\history\bundle.json --apply --api https://YOUR-CONFIRMED-DOMAIN/api/v1 --login foreman --output C:\Private\history\receipts.json
```

Первая команда — dry-run: никакого подключения к серверу/БД. Вторая требует явного --apply, проверенного HTTPS и пароля через getpass; redirects не следуются. Не передавать пароль аргументом и не помещать реальные пакеты/фото/квитанции в GitHub.

Перед первой записью проверяется весь пакет и доступ текущего пользователя ко всем объектам. Запись атомарна для отдельного отчёта, не для всей партии. После каждого успешного submit журнал квитанций записывается атомарно. При ошибке остановиться, проверить причину и повторить тот же пакет: принятые отчёты будут найдены по client UUID и не дублируются, потерянный ответ восстанавливается. Если содержимое существующей записи отличается или отчёт возвращён на исправление — импорт остановится, не меняя историю. Для исправлений использовать штатную revision-процедуру.

При наличии `source` он привязывается к черновику до submit и доступен по тому же ACL, что и отчёт. Повтор идентичен; изменение источника отвергается, при исправлении отчёта источник сохраняется. Ранее отправленные отчёты без источника нельзя задним числом пополнить этим API. Серверное время и автор по-прежнему относятся к импорту. Сопоставление исходного автора, объекта и фото остаётся ответственностью подготовившего пакет. Инструмент не превращает неполные исходники в доказанную производственную статистику.
