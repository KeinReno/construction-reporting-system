# AGENT_TASKS — точные пакеты GPT

## Общие правила
Читать `AGENTS.md`, `TASKS.md`, только релевантные документы. SPEC-00 до реализации спорных правил. Тесты обязательны: в отчёте приводить команду и результат. Не править чужие компоненты и общие контракты без согласования.

### SPEC-01/02 — архитектор, до отсчёта 5 дней
Согласовать B01–B14; заполнить SPEC-00, финализировать справочники и типы `work/no_work`, финоперации, ожидаемые отчёты; по API.md создать OpenAPI JSON/схемы DTO и mock endpoints. Приёмка: примеры синтетических ответов проходят валидацию, тесты контрактов проходят.

### DEV-01 (Android, день 1)
Только `android/`: Compose, экраны входа, объекты, рабочая форма, состав, несколько работ, no_work, материалы/инциденты/деньги по решению SPEC-00, фото, общий комментарий, Room. Приёмка: APK собирается, черновик переживает перезапуск без сети.

### DEV-02 (Android, день 2)
Только `android/`: WorkManager, UUID отчёта и вложений, idempotent draft/photo/submit, состояния local/queued/uploading/delivered, retry, 409/revisions. Использовать утверждённый mock API. Приёмка: обрыв, повтор, потеря ответа и конфликт проверены тестами.

### DEV-03 (Backend, день 3)
Только `backend/`: FastAPI, PostgreSQL, миграции, ACL, отчёты, назначения, ожидаемые сменные слоты, финоперации если B05, фото с sha256, submit транзакцией, versioning и журнал. Приёмка: AC-07…AC-21 тестами API/DB, mock контракт совместим.

### DEV-04 (Web, день 4)
Только `web/`: адаптивный интерфейс, контроль ожидаемых/полученных по сменам, разные статусы, работы/материалы/деньги без смешивания типов, инциденты, открытие первичных записей/фото. Приёмка: цифры совпадают с backend fixtures, iPhone viewport проверен.

### DEV-05 (Интеграция, день 5)
Сквозной путь телефон → сервер Windows → PostgreSQL/фото → дашборд, примитивный ограниченный AI read-only с fallback без ключа; smoke-test запуска. Приёмка: системный сценарий AC-07/AC-20/AC-24, протокол установки.

### QA-06…14 (вторая часть)
Использовать docs/ACCEPTANCE.md и docs/ROADMAP.md; дефекты как воспроизводимые записи с severity/шагами/ожиданием/фактом. Не считать отсутствующие проверки пройденными.

## Экономия токенов
Один агент кодирует, отдельный агент проверяет по контрольным точкам. Использовать адресное чтение файлов, маленькие диффы, короткие отчёты. Не подменять тесты объяснениями, не добавлять «на будущее» новые слои.
