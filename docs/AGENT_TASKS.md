# AGENT_TASKS — задания GPT

## Общая инструкция
На каждом задании: прочитать AGENTS.md, TASKS.md, только нужные контракты; выполнить минимальный объём; реально запустить проверки; обновить TASKS.md. Контракты не менять без согласования.

### DEV-01 (Android, день 1)
Создать Kotlin/Compose UI: вход, объекты, форма работ/материалов/инцидентов/фото/комментария, обязательные поля, локальный Room. Приёмка: APK собирается, офлайн-черновик сохраняется.

### DEV-02 (Android, день 2)
WorkManager, стабильный UUID, очередь отправки, повторное соединение, фото с контрольной суммой, статусы доставки. Приёмка: после обрыва отчёт отправляется один раз, полная доставка подтверждена серверным контрактом.

### DEV-03 (Backend, день 3)
FastAPI + PostgreSQL: миграции, роли, назначения, справочники, отчёты, серверная валидация, версии, вложения, аудит. Приёмка: API-тесты, права доступа, идемпотентность, полный submit.

### DEV-04 (Web, день 4)
React/TS: объекты, ожидаемые/полученные отчёты, фильтры, графики без смешения единиц, детали отчётов и фото, мобильный экран. Приёмка: расчёты совпадают с тестовой БД, ссылки на первичку.

### DEV-05 (AI/Integration, день 5)
Подключить ограниченные аналитические методы, LLM-провайдер без доступа к записи, Windows-развёртывание и сквозные тесты. Приёмка: один отчёт виден в Android/Web, ИИ отвечает с периодом/источниками, расчёты на сервере.

### QA-06…QA-14 (дни 6–14)
Проверки из docs/ACCEPTANCE.md и docs/ROADMAP.md; оформлять воспроизводимые дефекты. Не заменять приёмку простым визуальным просмотром.

## Экономия контекста
Никаких повторных больших пересказов, без переписывания чужих модулей, по одному маленькому PR/задаче, краткий итог: изменено / тесты / проблемы.
