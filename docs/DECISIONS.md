## Технические решения реализации 25.10.2026
| ID | Решение | Статус | Обоснование |
|---|---|---|---|
| ADR-013 | Отдельная optimistic lock_version для каждой записи отчёта; бизнес-revision только при изменении содержания | ACCEPTED | Одновременные submit/review/правки не теряют данные; проигравший получает 409 |
| ADR-014 | Имя файла attachment UUID + SHA256, replay разрешён и после submit | ACCEPTED | Проигравшая загрузка не перезаписывает успешный файл; потерянный submit-response восстанавливается |
| ADR-015 | Android token+owner в одном зашифрованном record; старые безымянные drafts не присваиваются следующему аккаунту | ACCEPTED | Авторство не должно зависеть от порядка входа |
| ADR-016 | Аналитик работает локально с явным intent до B13 | ACCEPTED | Можно проверить источники и числа без внешней передачи; свободный LLM-диалог не заявляется готовым |
| ADR-017 | Backup/restore только offline и в новый контур | ACCEPTED | Согласованный снимок БД/фото; запрет случайного затирания действующих данных |

Эти решения не закрывают бизнес-вопросы B01–B14. Руководитель проекта поручил продолжать все четыре компонента в существующем PR #2; статус SPEC-00 не изменён задним числом.


| ID | Решение | Статус | Обоснование |
|---|---|---|---|
| ADR-018 | Незавершённая Android-форма отдельно от очереди; owner+session nonce и атомарный enqueue/consume | ACCEPTED | Сохранять частичный ввод без автоотправки; не восстанавливать старую форму после принятой отправки; при отказе записи сохранить форму |

26.10.2026: Android поддерживает один активный редактор/форму аккаунта (`singleTask`). При переходе к исправлению другого отчёта замена текущей формы подтверждается пользователем. Это техническая защита данных, не утверждение открытых полей SPEC-00.
