# DECISIONS — реестр архитектурных решений

Обозначения: ACCEPTED — принято в рамках технической концепции; PROPOSED — требует согласования бизнес-правила; OPEN — не решено.

| ID | Решение | Статус | Обоснование |
|---|---|---|---|
| ADR-001 | Модульный монолит FastAPI+PostgreSQL; Android и Web используют один API | ACCEPTED | 10–20 отчётов/день, проще обслуживание |
| ADR-002 | Android offline-first, локальное сохранение, идемпотентный приём | ACCEPTED | Потери связи на стройплощадке |
| ADR-003 | Хранить фото отдельно с sha256 и связью с отчётом | ACCEPTED | Проверяемость и масштабирование |
| ADR-004 | Транспортный статус отдельно от бизнес-проверки | ACCEPTED | Уточнение не означает потерю доставки |
| ADR-005 | ИИ read-only через разрешённые функции, расчёты на сервере | ACCEPTED | Прозрачность и стоимость |
| ADR-006 | Один отчёт на бригаду × объект × смену по ответственному | PROPOSED (B01) | Удобная единица контроля |
| ADR-007 | Минимальный финансовый журнал включён в MVP | PROPOSED (B05) | Значимая доля реальных сведений |
| ADR-008 | Плановые отчёты по назначениям и графику объекта | PROPOSED (B02) | Нет ложных просрочек |
| ADR-009 | Внешний HTTPS без обязательного VPN, база не публикуется | ACCEPTED как цель; реализация OPEN (B11,B12) | Доступ с iPhone/ПК/Android |
| ADR-010 | API /api/v1, будущее подключение Orion через адаптер | ACCEPTED | Независимость продукта |
| ADR-011 | Обязательность фотографий, лимиты и сферы видимости | OPEN (B06) | Зависит от объекта |
| ADR-012 | Публичный GitHub содержит исключительно обезличенную документацию и код | ACCEPTED | Защита данных клиента |

Правила: любое изменение ключевого контракта фиксировать новой строкой и отражать в PRODUCT / DATA_MODEL / API / TASKS. Не редактировать историю принятых решений без пояснения.
