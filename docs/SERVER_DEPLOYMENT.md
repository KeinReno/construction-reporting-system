# Серверный контур CRS

Документ описывает развёрнутую архитектуру без адресов, паролей и содержимого базы. Частные пути и секреты остаются вне Git.

## Исходная точка

Рабочая база кода взята из открытого pull request #7, ветка `codex/project-completion-20261106`, коммит `6a532429edfd589f8fcd11a3f10a55db802146a4`. Проверки GitHub Actions для этого коммита на момент выбора были успешными: Android, Windows runtime, package, tests и обе сборки.

Ветка `main` на тот момент содержала ранние спецификации и не использовалась как запускаемый релиз. `codex/laptop-host-20261104` и `feat/mvp-core-bootstrap` являются предками выбранного коммита. Ветка `codex/production-analytics-20261106` не имеет общего предка с выбранным коммитом и сохранена в удалённом репозитории без автоматического слияния: в выбранном коммите уже есть более поздние операции владельца, миграция `0008` и трудовые итоги, а уникальные файлы параллельной ветки — черновые скрипты в `outputs/`.

Серверная интеграция ведётся в отдельной ветке и не переписывает `main`.

## Почему пути отличаются от примера C:\CRS

Системный диск небольшой, и учётная запись установки не входит в группу администраторов. Исходники, инструменты и проверенные пакеты размещены на отдельном диске данных. Рабочие данные PostgreSQL и фотографии размещены на другом физическом диске. Резервные копии лежат на третьем физическом диске, отдельно от данных.

| Назначение | Размещение |
| --- | --- |
| Git и исходники | каталог source на диске исходников |
| Проверенные пакеты | каталог releases |
| Тестовый контур | каталог staging и отдельная база |
| Конфигурация, кластеры PostgreSQL, фотографии | приватный каталог данных, не внутри Web и не в Git |
| Резервные копии | отдельный физический диск |

`C:\ProgramData\ConstructionReporting` не используется для базы и фотографий: на системном диске недостаточно свободного места для вложений.

## Контуры

Один компьютер обслуживает три логически раздельных контура.

- Source. Редактирование через Cursor и Git. Здесь выполняются сборка Web и упаковка релиза.
- Staging. Отдельный каталог пакета, виртуальное окружение, PostgreSQL `127.0.0.1:5433`, база `construction_staging`, API `127.0.0.1:8001`.
- Production. Отдельный каталог пакета, виртуальное окружение, PostgreSQL `127.0.0.1:5432`, база `construction`, API `127.0.0.1:8000`.

Роли приложения не являются суперпользователями PostgreSQL. Оба кластера слушают только `127.0.0.1`. `pg_hba.conf` разрешает SCRAM только с loopback и отклоняет IPv6. Порт 5432 не опубликован на внешних интерфейсах.

Web собран штатно (`tsc` и Vite) и входит в пакет. FastAPI отдаёт только `index.html` и файлы из `assets/`. Каталог вложений не входит в публичное дерево. Чтение фотографии идёт через `/api/v1/attachments/{id}` после проверки прав.

## Версии инструментов

Инструменты установлены в пользовательский каталог и не заменяют системные версии: системных Python, Node.js, PostgreSQL и Caddy до установки не было.

- Python 3.12.10, как требует `Install-Runtime.ps1`.
- Node.js LTS, использованный для `npm ci`, `tsc` и production-сборки.
- PostgreSQL 16.10, major совпадает с проверками backup в репозитории.
- Caddy как обратный прокси. Публичный доверенный сертификат зависит от домена и входящего доступа; см. журнал приёмки.

## Владелец

`owner_user_id` записан в приватный JSON только после создания активного пользователя с ролью `manager`, назначения ему объекта и чтения UUID командой `python -m app.cli owner-id`. Случайное имя владельцем не назначалось.

## Что не считается вводом в эксплуатацию

Публичный HTTPS с доверенным сертификатом, доступ с телефона вне локальной сети, физическая установка Android APK и перезагрузка Windows в этой установке не подтверждены. Причины и фактические проверки перечислены в журнале сервера, который не публикуется вместе с адресами и секретами.
