# CRS с домашнего ПК — временный HTTPS-доступ

Подготовлено и запущено 31.10.2026. Домен, VPS и изменение роутера для этого пилота не требуются. ПК должен оставаться включённым и иметь интернет. Рабочая копия данных находится вне репозитория в `B:\CRS-runtime`; оригинальная база не изменена.

## Для владельца

1. На рабочем столе открыть «СтройКонтроль — запуск с ПК». Откроется `http://127.0.0.1:58494/`.
2. Актуальную HTTPS-ссылку взять из `B:\CRS-runtime\ССЫЛКА.txt`. Заказчик открывает её в Safari. Настроенный шлюз srv.us сохраняет адрес по отдельному ключу проекта; этот ключ нельзя удалять или заменять, если нужен прежний адрес.
3. Данные входа находятся в `B:\CRS-runtime\ДОСТУП.txt`. Это приватный файл, его нельзя публиковать. Передать заказчику доступ самостоятельно.
4. Закрытие браузера сервер не останавливает. Для завершения открыть «СтройКонтроль — остановить».

Автоматический сон временно предотвращается процессом CRS; ручной сон, выключение, потеря интернета прерывают доступ. После запуска проверять ссылку. При обрыве шлюза ссылка временно удаляется из файла, сервер автоматически пробует переподключиться через 5 секунд. После восстановления файл снова содержит адрес. Если шлюз недоступен, локальные данные остаются на ПК.

## Устройство и данные

Один штатный API/Web на loopback 127.0.0.1, порт 58494. База SQLite и фото — `data` приватной рабочей папки, собранный Web — отдельный каталог `web`. Пароли, БД, конфигурация и первичные документы не раздаются как статика. Обычная серверная авторизация и ACL вложений сохранены; старые скопированные токены отозваны.

Входящий HTTPS обеспечивает исходящий SSH-туннель srv.us; Cloudflare-прокси не используется. HTTPS завершается на внешнем шлюзе: веб-трафик проходит через него, БД и файлы хранятся на ПК. Для SSH отключены личные ключи, агент и пользовательский config; используются отдельный known_hosts и отдельный gateway_ed25519, созданный только для этого пилота. Это временный просмотр/пилот, без гарантии доступности в каждой сети РФ. Промышленная эксплуатация требует отдельного решения. Зависимости DNS/TLS провайдера отдельно от маршрута трафика не контролируются приложением.

Перенесено 94 отчёта и 247 фотосвязей к 237 уникальным файлам. Первичные записи, ревизии и квитанции сохранены. Фото, связанные только по дате, обозначены отдельно. Дополнительные не связанные материалы остались в прежней приватной папке; импортировать их следует отдельно после проверки. `backup-before-conversion` — резервная копия до материализации, она не заменяет резервную копию текущей базы и uploads.

Локальные запуск → остановка → повторный запуск проверены. Независимый QA: read-only вход/выход, 94 отчёта, источники/фото, 390/768/1440 px без переполнения и ошибок JS. Неавторизованные отчёты/фото дают 401; владелец не получает admin (403); приватные пути дают 404. Публичный HTTPS через шлюз: вход, 94 отчёта и защищённая фотография подтверждены. Проверка физического iPhone через мобильную сеть РФ остаётся NOT_TESTED до ответа владельца. Доказательства находятся в приватной папке `B:\CRS-runtime\qa`.

Первая попытка владельца с iPhone: сайт вообще не открылся. В этот момент шлюз уже закрыл SSH-соединение, а файл ещё содержал неработающий адрес. Исправлены reconnect и удаление устаревшего адреса. Принудительный обрыв собственного SSH воспроизвёл проблему: статус disconnected, ссылка очищена; затем автоматическое восстановление с новым адресом и HTTPS `/ready` 200, процесс API остался тем же. Повторная проверка владельцем ожидается; доступность конкретной мобильной сети пока не подтверждена.

Повторная попытка не удалась также на Android. Обнаружена очередная смена имени localhost.run; этот провайдер заменён на srv.us. После переключения root/Web 200; принудительный обрыв SSH → автопереподключение с тем же адресом → ready 200, API не перезапускался. `pytest backend/tests/test_local_preview.py -q` — 2 PASS (фильтр адресов, изоляция отдельного ключа). Повторная проверка телефонов с новым провайдером ожидается. Нельзя считать ответы с ПК доказательством доступности мобильной сети.

## Для сопровождения

Скрипты `scripts/windows/Start-LocalPreview.ps1` и `Stop-LocalPreview.ps1` по умолчанию используют `B:\CRS-runtime`; параметр `-DataRoot` задаёт другую подготовленную папку. `-LocalOnly` запускает без шлюза, `-NoBrowser` не открывает браузер. `local_preview.py` обновляет running.json и ССЫЛКА.txt при выдаче нового адреса; остановка через stop.request завершает только собственные сервер/SSH. Приватные логи лежат там же.

`prepare_local_preview.py --source <private-source> --target <new-private-folder>` создаёт отдельную копию, отказывается перезаписывать существующую папку; перед применением к другой базе обеспечить остановку её сервиса. Нужны установленное окружение `.venv`, системный ssh, собранный `web/dist` и текущие исходники. Это не автономный EXE: папку репозитория и runtime сохранять. Новые данные в рабочей копии не синхронизируются обратно в прежнюю базу автоматически.

Выбор провайдера задаётся `gateway` в приватном config.json: `srv.us` требует отдельный файл gateway_ed25519 в runtime; `localhost.run` оставлен только для совместимости старой конфигурации. При подготовке нового runtime скриптом по умолчанию сохраняется прежний провайдер: srv.us настраивать явно вместе с отдельным ключом. Не использовать личные SSH-ключи. Официальные сведения: [srv.us](https://docs.srv.us/), [ограничения прежних бесплатных адресов](https://localhost.run/docs/forever-free/).
