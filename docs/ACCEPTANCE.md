# ACCEPTANCE — матрица приёмки MVP v0.2

Каждый сценарий имеет `PASS / FAIL / BLOCKED / NOT_TESTED`, среду, время, шаги, ожидалось/получено, ссылку на дефект и исполнителя. Никаких «прошло», если не запускалось.

## Android / рабочая форма
- AC-01: доступ только к назначенным объектам; сменный отчёт с несколькими видами работ.
- AC-02: обязательные поля валидируются; комментарий может быть пуст; «Другое» имеет уточнение.
- AC-03: no_work + причина проходит, без фиктивного объёма; инцидент может существовать без выполненных работ.
- AC-04: участники бригады не подменяют автора; привлечённые сотрудники представлены отдельно.
- AC-05: денежные операции разных типов, суммы/даты/чеки не смешиваются (если B05 включён).
- AC-06: несколько фото сохраняются локально, без потери при перезапуске.

## Надёжность / ревизии
- AC-07: отправка без сети → queued, после восстановления → один отчёт и квитанция.
- AC-08: оборвать сеть между submit и ответом → повтор не создаёт дубликат.
- AC-09: обрыв одного фото → нет «delivered» до stored/submit.
- AC-10: отправка идентичного ID с другим payload → 409; данные не перетёрты.
- AC-11: две одновременные правки одной revision → 409, история сохранена.
- AC-12: returned needs_revision → исправлено → повторно submitted с новой revision, receipt сохраняется.
- AC-13: выключить Android/перезапустить Windows между операциями → восстановить очередь/подтверждение без потерь.

## Права и безопасность
- AC-14: 401 без входа; 403 для чужого объекта, отчёта, фото, финансовых записей.
- AC-15: подмена author_id в запросе не даёт подменить автора.
- AC-16: токены/пароли/персональные данные отсутствуют в Git и логах; HTTPS обязателен; БД закрыта.
- AC-17: резервная копия БД+фото фактически восстанавливается на тестовом контуре.

## Дашборд и расчёты
- AC-18: ожидаемые отчёты учитывают назначения/смены/выходные/дедлайны; no_work не числится пропуском.
- AC-19: «доставлено» и «проверено» показываются отдельно, изменения видны в истории.
- AC-20: объёмы разных единиц не складываются; нет плана — нет процента готовности.
- AC-21: получено/израсходовано материалов и разные денежные операции отражены отдельно, накопительные итоги не дублируются.
- AC-22: график и сумма открываются в соответствующие исходные отчёты, фото и фильтры.

## ИИ и эксплуатация
- AC-23: ИИ использует разрешённые функции, даёт ссылки, периоды, единицы, ограничения; не принимает инструкции из комментариев как команды.
- AC-24: без провайдера/ключа ИИ основные графики и Web работают.
- AC-25: Windows-сервис восстанавливается после перезапуска; браузер ПК/iPhone и Android работают с доступом по HTTPS и без обязательного VPN в согласованных сетях.
- AC-26: есть процедуры обновления/отката и учёт критических дефектов.

## Выходные критерии
К дню 5 — хотя бы один сквозной интеграционный сценарий. К дню 14 — все **применимые** P0 без FAIL, остальные дефекты классифицированы; владелец клиента подписывает решение о пилоте. Неприменимые тесты отметить N/A с причиной, не выдавать за PASS.
