# ACCEPTANCE — критерии приёмки MVP

## Форма Android
- Авторизация и только назначенные объекты.
- Обязательные поля и единицы измерения валидируются.
- Отдельный сценарий «работ не было».
- Несколько работ и фото; необязательный комментарий.
- Отчёт сохраняется при выключенном интернете.

## Передача
- После восстановления сети отчёт передаётся автоматически.
- Повторная отправка того же client_report_id не создаёт дубль.
- Обрыв при фото не создаёт ложный статус полной доставки.
- Состояние «Доставлен» появляется только после server submit.
- Исправление возвращённого отчёта сохраняет историю версий.

## Права
- Работник не читает отчёты/фото других объектов без разрешения.
- Сервер не принимает подменённый author_id.
- Без авторизации API недоступен.
- Прямой публичный доступ к PostgreSQL отсутствует.

## Дашборд и аналитика
- Статус «не отчитался» учитывает назначение и график.
- Фильтры и итоги сверяются с исходными отчётами.
- Не суммируются несопоставимые единицы.
- План-факт без плана не рассчитывается.
- ИИ ссылается на исходные данные; неподтверждённые причины обозначает гипотезами.

## Эксплуатация
- Windows restart не теряет данные.
- Резервная копия реально восстанавливается.
- HTTPS и работа без обязательного VPN проверены в целевых сетях.
- Проверены Android, iPhone (Web) и настольный браузер.

Для каждого теста записать дату, среду, шаги, результат и дефект при неуспехе. Невыполненный тест отмечать NOT_TESTED, а не PASS.
