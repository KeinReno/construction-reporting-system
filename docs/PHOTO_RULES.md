# PHOTO_RULES — фото и чеки

**Политика обязательных фото и лимиты пока OPEN B06.**

- Фото имеет `attachment_id UUID`, `report_id`, optional work_entry_id / incident_id / financial_entry_id, mime, size, checksum sha256, storage status, server uploaded_at, optional EXIF taken_at.
- Android сохраняет фото в app-private локальном пространстве до подтверждения доставки; недоступность сети не уничтожает черновик/файлы.
- Фотографии загружаются отдельно, с идемпотентным ключом attachment_id + checksum. Повтор с другим содержимым даёт 409. Сервер валидирует file signature, MIME, размер, checksum и доступ пользователя; физическое сохранение атомарно.
- Последовательность: draft → attachments verified/stored → submit. Никакой успешной квитанции, если требуемые фото недоставлены.
- Вся галерея и миниатюры доступны только через авторизованный API; не выдавать публичные постоянные ссылки.
- Дата из EXIF может быть неверной; при построении хронологии не считать её автоматически датой работ.
- Фото чека относится к конкретной денежной записи; фото объекта — к работе/инциденту или отчёту.
- Коррекция/удаление фиксируется новой ревизией; не стирать исходные доказательства без отдельной политики хранения.
- Сжатие/миниатюры допускаются с сохранением выбранной политики оригиналов; лимиты и сроки удаления утверждает заказчик.
- При будущем импорте истории MAX связь с сообщением/датой может быть неоднозначной — отдельный статус «не подтверждена». **Сам импорт не входит в MVP.**
- Никогда не помещать реальные вложения, имена и переписку клиента в GitHub.
