# PHOTO_RULES — вложения и фотографии

- Каждое фото получает стабильный attachment_id, sha256, размер, медиатип и отдельный статус загрузки.
- Снимок относится к report_id, опционально work_entry_id, incident_id или expense_id.
- Фото сначала сохраняется локально; при отсутствии связи синхронизация продолжается позднее.
- Сервер проверяет тип, лимит размера, права доступа, целостность и принадлежность отчёту.
- Завершение отчёта невозможно, пока обязательные фото не загружены и не зафиксированы сервером.
- EXIF taken_at — дополнительная ненадёжная метка, uploaded_at задаёт сервер. Сопоставление по дате не равно подтверждению связи.
- Миниатюры и оригиналы доступны только через авторизованные маршруты API.
- Не помещать реальные фото заказчика, чеки, паспорта, переписки и персональные данные в GitHub.
- Для будущего импорта истории MAX хранить первичный идентификатор сообщения/группы и явную или подтверждаемую связь с фото; сомнительные связи помечать для ручной проверки.
- Не дублировать физический файл при повторной загрузке с тем же attachment_id и checksum. Ошибка совпадения ID и содержимого — конфликт.
- Удаление/исправление вложений должно отражаться в журнале аудита.
