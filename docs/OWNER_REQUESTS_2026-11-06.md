## 3. Границы учёта, зафиксированные в расчётах

Эти пункты сервер возвращает в `limitations`, чтобы цифры не читались как готовые факты:

- Учитываются только отправленные и проверенные отчёты; день без отчёта — отсутствие данных, а не выходной.
- Дни по видам работ считаются по формулировкам; одна смена может дать несколько показателей; это не объём и не процент готовности.
- Т1/Т2 читаются из текста смены: поле в форме ещё не подключено, исторические смены в основном «трансформатор не указан».
- Погода видна только там, где названа; отсутствие записи не означает ясную погоду.
- Часы техники заявлены отправителем и подняты из первички без переноса в проекцию; часы строкой «Работа спецтехники: N часов» без вида техники показаны отдельно и не распределены по машинам.
- Дни по людям считаются по составу бригады в написании автора; похожие имена не объединяются автоматически, а вынесены в список на сверку.
- Сварка без указания объекта отнесена к сварке металлоконструкций; сварка сетки и армопояса осталась в своих показателях.
- Временным помечен только работник с номером в названии; признак временного сотрудника в форме отчёта ещё не заполняется.

## 5. Постоянные ограничения проекта (действуют на все пункты)

- Приоритеты: сохранность и корректность данных → доступ и безопасность → прозрачные расчёты → UX → дополнительные функции.
- Одна задача — один изолированный набор изменений, тесты и короткий отчёт; статусы в `TASKS.md` меняются только после доказательной проверки.
- Без микросервисов, брокеров и Kubernetes: одна БД, один API, один Web, Android-клиент.
- Денежные суммы — целочисленные копейки; количество — Decimal; транспорт и бизнес-статус разделены.
- Отчёты и ревизии не перезаписываются молча: `expected_revision`, конфликт 409, журнал исправлений.
- ИИ без произвольного SQL и без права записи, только разрешённые серверные аналитические функции; численные расчёты делает сервер, не модель.
- В репозиторий нельзя класть реальные документы, фото, внутренние данные и секреты: используется синтетика. Живая пилотная база (`C:/CRS-Live`) не коммитится и не правится без отдельного задания.
- Не заявлять SUCCESS без запуска тестов; незакрытое помечается `BLOCKED` / `NOT_TESTED` с командой проверки.

## 7. Выполнение и уточнения 06.11.2026 (приоритет над ранними статусами)

- Владелец подтвердил архивирование удаляемых работ, сохранение истории, группы main/auxiliary/special и основного родителя вспомогательной работы. Реализованы API, миграция, отдельный Web-раздел, выбор в формах и связь с аналитикой; старые названия зарезервированы.

Суммы в копейках; корректировки с причиной; UUID/expected_revision/аудит защищают повторы и исправления. Исторические похожие имена автоматически не объединяются и начисления из них не создаются.

Автоматической синхронизации с MAX и гарантированного открытия живого MAX внутри iframe нет: используются сохранённые корпуса/источники с ACL. Полная переписка автоматически ИИ не передаётся.
- Исправлены найденные QA ошибки дней на нескольких объектах, людей из no_work, календаря, погоды, мобильных таблиц и независимой загрузки production.
- Публикация выполняется новой веткой поверх существующей истории GitHub; локальная история Квена сохранена резервной локальной веткой. Приватный outputs с реальными аудиторскими выдержками исключён из новой ветки, рабочие БД/фото не включены.
- Команды, доказательные результаты и оставшиеся ограничения: AUDIT_RELEASE_2026-11-06.md. Физический телефон, перенос на ноутбук, рабочая миграция и внешняя эксплуатационная приёмка не объявляются завершёнными заочно.
