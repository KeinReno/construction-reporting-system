# CRS: перенос рабочего контура на ноутбук

Статус: **IN_PROGRESS**. На текущем ПК создана приватная проверенная копия. Физический ноутбук и Android пока недоступны для приёмки.

## Что переносится

Приватная папка `B:\CRS-laptop-transfer-20261104` содержит снимок исходной SQLite БД, восстановленный рабочий runtime, Web и все 564 медиафайла. В БД 94 отчёта, 247 связей фотографий, 2 объекта. `runtime-manifest.json` содержит SHA-256 всех 638 файлов, перед установкой и после копирования они проверяются. Исходная папка `B:\CRS-runtime` не изменена.

В перенесённой копии существующий аккаунт руководителя переименован в `Andrey` с сохранением ID, истории и назначений. Создан `Ispolnitel` с ролью foreman и доступом к обоим объектам. Исторический автор `max-import` сохранён, но его вход отключён. Все прежние серверные сессии в копии отозваны. Пароли заданы владельцем проекта в чате и **не записаны в репозиторий или инструкцию**. Это согласованное временное исключение для двух коротких паролей в приватном контуре; общий API по-прежнему требует минимум 12 символов при создании других пользователей.

## Установка на ноутбуке

1. Перенести **приватно** всю папку `B:\CRS-laptop-transfer-20261104` и архив исходников из неё на ноутбук. Не загружать папку с данными в GitHub, облачный диск или общий чат. Переносной носитель хранить под контролем владельца.
2. Распаковать `CRS-source.zip` в отдельную папку, например `C:\CRS-code`. Установить Python 3.12 и Windows OpenSSH Client. Доступ к интернету нужен для однократной установки Python-зависимостей и для HTTPS-шлюза. Стандартный сетевой Android APK опубликован отдельно: https://github.com/KeinReno/construction-reporting-system/releases/download/crs-android-0.4.1-pilot-20261104/CRS-Android-0.4.1.apk . Это debug-подписанная сборка 0.4.1, не demo APK; если на телефоне уже есть CRS с локальными черновиками, сначала сохранить их перед переустановкой.
3. В PowerShell из папки исходников выполнить:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\windows\Install-TransferredHost.ps1 -TransferRoot 'E:\CRS-laptop-transfer-20261104' -DataRoot 'C:\CRS-Live'
   ```

   Заменить `E:` на букву носителя. Установщик откажется работать, если `C:\CRS-Live` уже существует. Он проверит контрольные суммы, установит серверные зависимости, скопирует данные и Web, создаст отдельный ключ HTTPS и ярлыки запуска/остановки. Его нельзя запускать поверх существующей БД.
4. Открыть `C:\CRS-Live\START-HERE.txt`, затем `START-CRS.cmd`. Запускатель сначала проверяет локальный API `/ready`, затем публичный HTTPS `/ready`, сверяет идентификатор одного экземпляра сервера на обоих адресах и только после этого открывает Web. Если HTTPS за 60 секунд не подтвердился, запускатель сообщает об этом и не открывает страницу входа; проверьте интернет и запустите `START-CRS.cmd` ещё раз. Адрес также записывается в `ССЫЛКА.txt`. Войти как `Andrey`.
5. В Android ввести тот же HTTPS-адрес с суффиксом `/api/v1`, войти как `Ispolnitel`; на втором браузерном экране открыть тот же Web. Отправить **новый** отчёт и сверить его серверную квитанцию, ID и содержимое в обоих браузерах. Это обязательная физическая приёмка.

## Ограничения

Снимок фиксирует данные на момент копирования. Если в исходный CRS позже добавят отчёты, перенос нужно повторить новым полным снимком до работы с ноутбука; две SQLite БД автоматически не синхронизируются. После начала ввода новых отчётов на ноутбуке этот ноутбук становится источником актуальных данных, и его нужно регулярно резервировать. Один и тот же переносный каталог с реальными данными не следует хранить в нескольких доступных всем местах.

После встречи сменить оба временных пароля на уникальные длиной от 12 символов через администратора; для этого понадобится отдельный администраторский доступ или процедура смены паролей. Заказчик должен утвердить канал HTTPS и режим эксплуатации перед постоянным серверным размещением (SPEC-00 B11/B12/B14 остаются OPEN).
