# CRS — Shark UI: отбор компонентов и план внедрения

Дата: 2026-10-31. Статус: UI/UX implementation brief; код компонентов ещё НЕ интегрирован. Основа: `feat/crs-uiux-redesign-v2`.

## Источники
- Каталог: https://shark-ui.com/docs/components/
- Приоритет владельца: https://shark-ui.com/docs/components/sidebar и https://shark-ui.com/docs/components/progress
- Установка: https://shark-ui.com/docs/installation — обязательный Tailwind CSS v4.

## Решение
НЕ ставить весь Shark UI и НЕ переписывать бизнес-логику. Переносить визуальные и доступные примитивы в React/Vite по экранным блокам. Android Jetpack Compose НЕ может напрямую использовать React-компоненты: переносить дизайн-паттерны нативно.

### P0: первый пакет редизайна Web (брать сейчас)
| Компонент | Применение в CRS | Ограничение |
| --- | --- | --- |
| Sidebar | Вместо текущего `aside.sidebar`; компактный icon-rail на десктопе, разделы, активный пункт, права доступа | `variant=inset`, `collapsible=icon`; не ломать маршрутизацию и админ-доступ |
| Progress | Отправка фото/файлов и показатели, где есть достоверный знаменатель | НЕ вычислять выдуманный «процент готовности строительства» |
| Table | Журнал отчётов и финансовые перечни, плотные строки, устойчивые заголовки и действия | Сохранить семантику HTML table, текущие фильтры и сортировку |
| Status + Badge | Статусы отчётов, привязка к бизнес-состояниям и числовые маркеры | Не смешивать транспортные состояния Android с серверными бизнес-статусами |
| Date Picker + Calendar | Периоды, даты отчётов и журнал; выбор одного дня и диапазона | Сохранить локальный формат даты и существующую валидацию |
| Combobox | Поиск и выбор объектов, сотрудников, фильтров | Не использовать несколько разных searchable-select паттернов одновременно |
| Segment Group | Выбор «Список / Карточки», период «День / Месяц / Год» | Это переключение режима в рамках экрана, не навигация |
| Tabs | «Работы / Ресурсы / Фото / Проверка» внутри деталей отчёта по необходимости | Не прятать критические решения проверки |
| Chart | Аналитика по отчётам/объектам с существующими данными | Recharts; не придумывать новые KPI и серверные методы |
| Menu | Контекстные действия со строкой журнала и объектом | Вписывать в существующие права и сценарии |
| Dialog + Alert Dialog | Просмотр и подтверждение рискованных действий | Не превращать основные рабочие экраны в каскад модалок |
| Toast + Skeleton | Достоверная обратная связь и загрузочные состояния | Ошибка/успех только по фактическому результату операции |

### P0-support: установить адресно вместе с экраном
- `Field`, `Input`, `Input Group`, `Textarea`, `Number Input` — для доступных унифицированных форм ввода чисел и комментариев, если Web-форма их использует.
- `Tooltip` — пояснение иконок свернутого Sidebar; на touch не должен быть единственным способом объяснения.
- `Breadcrumb` — цепочка «Объекты / [Объект] / [Отчёт]» в глубоких экранах.
- `Pagination` — журнал при наличии серверной/клиентской пагинации; не добавлять её только ради компонента.
- `Bottom Navigation` — адаптивный Web на узких экранах, с ограниченным числом основных разделов; сохранить остальные через меню. Android — нативный Compose.
- `File Upload` — только там, где веб-интерфейс действительно загружает вложения; Android-загрузка остаётся нативной.

### P1: после базовой визуальной миграции
- `Data List` — ключ/значение и атрибуты отчёта/объекта.
- `Collapsible` / `Accordion` — второстепенные фильтры и длинные блоки деталей.
- `Scroll Area` — боковое меню и длинные панели.
- `Resizable` — панель просмотра отчёта + контекст проверки, если макет реально выигрывает.
- `Action Bar` — только после появления разрешённого сценария множественного выбора; не создавать массовые операции ради UI.
- `Command` — единый поиск и быстрые команды после подтверждения сценариев.
- `Circular Progress` — компактный показатель только при реальной количественной базе; не дублировать линейный Progress.
- `Alert`, `Announcement` — ненавязчивые системные предупреждения, если нужны на конкретных экранах.
- `Image Cropper` — только по отдельной потребности в редактировании фото; фото как доказательства не менять молча.

### Отложить/не брать сейчас
`Floating Panel`, `Drawer`, `Sheet` (кроме узкого временного фильтра по реальной необходимости), `Tree View`, `Tour`, `Carousel`, `Marquee`, `Rating`, `Circular Slider`, `Color Picker`, `QR Code`, `Signature Pad`, `Timer`, `Input OTP`, `Context Menu` и декоративные эффекты. Они не решают текущую основную задачу CRS или требуют новых рабочих сценариев. Не делать обилие выезжающих панелей.

## Критерии приёмки
- Web: одинаковая иерархия и единые tokens на главной, объектах, журнале, аналитике и деталях.
- Все доступные действия и статусы привязаны к текущим данным/правам, без имитаций.
- Десктоп sidebar реально сворачивается в icon rail, и подписи доступны с клавиатуры.
- Узкий экран не показывает все семь разделов в одной нижней полосе; навигация не перекрывает контент.
- Таблицы читабельны, даты локализованы, пустые/загрузочные/ошибочные состояния различимы.
- Проверка интерфейса на 390, 768, 1440; клавиатурная навигация, фокус и контраст.

Это спецификация выбора. Она НЕ означает, что компонентный код установлен или что сборки/тесты выполнены.
