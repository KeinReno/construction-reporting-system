# ROADMAP — SPEC-00 + 5 дней разработки + 9 дней пристрелки

**Важно:** SPEC-00, обследование сервера, утверждение справочников и API — предварительная контрольная точка до начала пяти дней. Если это не завершено, оценка 5 дней не гарантируется.

| Период | Цель | Результат |
|---|---|---|
| SPEC-00 | Бизнес-правила B01–B14, OpenAPI, mock, среда | Согласованный scope и контракты |
| День 1 | Android: Compose, форма (work/no_work), Room, фиктивный API | Локальный черновик и APK |
| День 2 | Android: WorkManager, фото, retry, conflict, receipt | Контрактные тесты и очередь |
| День 3 | Backend: FastAPI, PostgreSQL, ACL, отчёты/фото, минимальные финансы если B05 | Рабочие миграции и API-тесты |
| День 4 | Web: KPI, объекты, ожидаемые отчёты, финансы/материалы, фильтры | Реальные серверные показатели |
| День 5 | E2E, Windows тестовый запуск, аналитика и опциональный LLM | MVP 0.1 интегрирован |
| День 6 | Сквозные сценарии | Переход из Android в Web |
| День 7 | Офлайн, повторы, загрузка фото, conflict | Надёжность доставки |
| День 8 | Права, сеть с VPN/без, backup/restore | Безопасность и восстановление |
| День 9 | Реальные полевые испытания 3–4 ответственных | UX-дефекты |
| День 10 | Сверка расчётов/периодов/источников, ИИ | Достоверность аналитики |
| День 11 | UX и багфиксы | Правки по приоритетам |
| День 12 | Регрессия/нагрузочные сценарии | Стабилизация |
| День 13 | Windows deploy, инструкции, обновление и откат | Релиз-кандидат |
| День 14 | Приёмка заказчиком | Решение о пилоте, протокол дефектов |

Если к дню 5 возникает нехватка времени: P0 (надёжная доставка, API, Web, роли, сохранность) нельзя урезать ради ИИ; LLM отключаем, оставляем серверную аналитику. С дня 6 — заморозка новых функций, кроме исправлений блокирующих ошибок.
