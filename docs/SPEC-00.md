# SPEC-00 — обязательное согласование до старта кода

**Статус: PARTIAL (28.10.2026).** Владелец проекта разрешил самостоятельно принять рабочие решения по продукту и UX: пять настраиваемых отправителей, один проверяющий заказчик, остальные правила по текущей практике. Эти решения описаны в [PRODUCT_DECISIONS_2026-10-28.md](PRODUCT_DECISIONS_2026-10-28.md). Параметры Windows 10, сети, эксплуатации и окончательной приёмки остаются открытыми; весь SPEC-00 не утверждён.

| ID | Вопрос | Предлагаемая опция (PROPOSED) | Важность |
|---|---|---|---|
| B01 | Кто и сколько отчётов сдаёт? | Ответственный за бригаду × объект × смену; несколько работ в одном отчёте, дополнительные отчёты допустимы | BLOCKER |
| B02 | Какое расписание сдачи и просрочки? | Ожидание только при назначенной смене + дедлайн в часовом поясе объекта; выходные исключить | BLOCKER |
| B03 | Какие поля обязательны для каждого типа объекта? | Объект, рабочая дата, бригада/ответственный, `work` либо `no_work`+причина; категории и фото настраиваемые | BLOCKER |
| B04 | Как учитывать состав бригады/наёмных? | Справочник работников отдельно от логинов, разовый временный состав, история назначений | BLOCKER |
| B05 | Нужны ли расходы/финансирование/авансы в MVP? | Да, минимальный денежный журнал: расходы, поступления и выдачи, без бухгалтерии | BLOCKER |
| B06 | Фото: когда обязательны, число и размер? | По типу работ; можно без фото там, где не требуется; лимиты конфигурируемы | IMPORTANT |
| B07 | Справочники работ/материалов, измерения и «Другое» | Предзаполненные категории + уточнение «Другое», не создавать справочник из каждого текста | IMPORTANT |
| B08 | Работа с уточнениями и проверкой | Возврат на исправление; оригинал и все ревизии сохраняются | IMPORTANT |
| B09 | Какие KPI руководителю действительно нужны? | Дисциплина, объёмы по сопоставимым единицам, материалы, расходы, инциденты | IMPORTANT |
| B10 | Нужны ли планы следующей смены на первом этапе? | Короткие структурированные пункты, без полноценного задачника | IMPORTANT |
| B11 | Какой Windows-сервер и кто администрирует? | Осмотр ОС, ресурсов, дисков, служб, доступа, резервных копий | BLOCKER |
| B12 | Доступ без VPN и политика данных | HTTPS-шлюз, выбор после тестов; БД/фото только у клиента, облачные данные — по разрешению | BLOCKER |
| B13 | ИИ-провайдер, бюджет и разрешённая передача данных | Обезличенные агрегаты, лимиты и отключаемый режим | IMPORTANT |
| B14 | Кто принимает систему, сопровождение и права на код | Заказчик утверждает сценарии и обязанности обслуживания | BLOCKER |

## Документы при завершении SPEC-00
- Утверждённые справочники, шапка/типы формы, варианты «работ нет», смены, ожидаемые отчёты.
- Синтетические тестовые отчёты: работа с несколькими операциями; простой; деньги без работ; исправление поздних расходов; фото + чек.
- OpenAPI схемы запросов/ответов и mock API; схема БД; правила финансовых операций.
- Характеристики Windows и техническая проверка HTTPS с VPN/без.
- Понятные критерии приёмки MVP на день 5 и день 14.
