# Сопровождение серверного контура CRS

Команды ниже рассчитаны на уже подготовленный сервер. Секреты читаются из приватного JSON и файлов паролей. Их не передают аргументами командной строки и не помещают в Git.

## Расположение

Приватная схема каталогов описана в `docs/SERVER_DEPLOYMENT.md`. Файл `layout.json` рядом с операционными журналами, вне Git, содержит конкретные пути этой машины: исходники, Python, Node.js, `CRS_PG_BIN_DIR`, Caddy, каталоги production/staging, конфиги, каталог backup и файл состояния релиза.

## Запуск и остановка

PostgreSQL запускается из каталога бинарников:

```powershell
& "$PgBin\pg_ctl.exe" -D $ProductionData -l $ProductionLog -w start
& "$PgBin\pg_ctl.exe" -D $StagingData -l $StagingLog -w start
```

Остановка кластера: `pg_ctl.exe -D $Data -m fast stop`.

API production и staging запускаются только через `scripts\windows\Run.ps1` с абсолютным путём приватного конфига. Скрипт мигрирует схему, держит один процесс и не пускает второй экземпляр с тем же каталогом данных. Порт production — 8000, staging — 8001. Оба слушателя остаются на `127.0.0.1`.

Проверка: `http://127.0.0.1:8000/ready` и `http://127.0.0.1:8001/ready` возвращают `{"status":"ready"}`. `/health` означает только живой процесс и не заменяет `/ready`.

Остановка API — завершение процесса, слушающего соответствующий порт. После остановки mutex освобождается, и `Run.ps1` можно запустить снова.

Автозапуск оформлен задачами Планировщика для текущего входа в систему. Задача на старт до входа пользователя и официальный `Register-Startup.ps1` требуют пароль отдельной учётной записи и право регистрировать задачу AtStartup. Пока этого нет, контур поднимается при входе оператора, а не как служба до логона.

## Обновление

1. Изменить код в ветке серверной интеграции и сохранить его в Git.
2. `Deploy-CRS.ps1 -Action Preflight`.
3. `Deploy-CRS.ps1 -Action Build`.
4. `Deploy-CRS.ps1 -Action StagingCheck` на порту staging и отдельной базе.
5. `Deploy-CRS.ps1 -Action Backup`. Скрипт останавливает production API, снимает копию штатным `python -m app.backup`, проверяет SHA-256 манифеста и снова запускает API.
6. `Deploy-CRS.ps1 -Action Deploy`. Новый каталог не затирает предыдущий. Состояние записывает текущий и предыдущий пути.
7. Проверить `/ready`, вход и открытие уже существующего отчёта.

Небольшое изменение Web или Backend проходит тот же порядок. Нельзя править файлы внутри каталога production как единственную копию исходников.

## Откат

`Deploy-CRS.ps1 -Action Rollback` переключает процесс на предыдущий каталог релиза, только если Alembic head обоих каталогов совпадает. Скрипт не выполняет `alembic downgrade`.

Если миграция уже изменила схему, откат — это восстановление согласованной копии в новую пустую базу и запуск той версии приложения, с которой копия была снята. Старую базу при этом не перезаписывают.

Восстановление:

```powershell
$env:CRS_PG_BIN_DIR = $PgBin
$env:DATABASE_URL = '<URL новой пустой базы>'
$env:UPLOAD_DIR = '<новый пустой каталог>'
python -m app.backup verify <snapshot>
python -m app.backup restore <snapshot> --service-stopped
```

API на время backup и restore должен быть остановлен. Restore отказывается писать в непустой каталог фотографий и в непустую базу.

## Диагностика

- `/ready` отвечает 503: смотреть миграции и доступность PostgreSQL, не открывая базу наружу.
- API не слушает порт: `api.err.log` в каталоге контура. Повторный запуск при живом процессе завершается сообщением о mutex.
- `pg_isready` на `127.0.0.1` и нужном порту. Если кластер не поднялся после перезапуска сессии, сначала запустить `pg_ctl`, затем API.
- Место на диске данных и диске копий проверять до приёма фотографий. Копия не заменяет проверку свободного места.
- Вложения больше 8 МБ и файлы с чужой сигнатурой API отклоняет. Прямой URL файла в каталоге uploads веб-сервером не публикуется.

## Учётные записи

Первые `admin`, `manager` и `foreman` созданы локальной командой `python -m app.cli`. Пароли лежат в приватном каталоге секретов с правами оператора. На Windows `getpass` читает консоль, поэтому неинтерактивный ввод нужно подавать внутри процесса, не печатая пароль. Дальнейшие пользователи создаются в веб-разделе управления.

Роли HTTP-аккаунтов: `admin`, `manager`, `foreman`. Отдельной роли с именем employee в коде нет: сотрудник входит как `foreman`. Интерфейс сотрудника открывается как `/?mode=employee` на том же origin, что и кабинет руководителя.

## Проверки, которые остаются на владельце

Нужны согласованные домен, входящий TCP 80/443 или явно одобренный туннель, правило брандмауэра и право администратора для постоянной службы до входа в систему. Самоподписанный сертификат не используется как рабочий адрес Android. Пока публичного имени нет, Caddy может обслуживать только локальную проверку; это не внешний адрес для телефонов.
